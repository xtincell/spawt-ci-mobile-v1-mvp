## 2. Ce qui a marché

### 2.1. CR Chunk A en mode no-tech-debt

Le sweep adversarial a remonté 64 findings. Le user a explicitement demandé "no debt mode" → toutes les CRITIQUE/MAJEUR ont été soit patches, soit décisions structurelles (D1 RPC PL/pgSQL atomique, D2 real Gold gate avec AxisBar, D4 sync writer), pas de défer silencieux.

Notamment :
- **D1** : remplacement du 2-step UPDATE non-atomique `setDisplayedTitre` par RPC PL/pgSQL `set_displayed_title(uuid, text)` SECURITY INVOKER atomique. Plus de risque "0 titre affiché côté serveur".
- **D2** : implémentation d'un vrai gate Gold dans `PalaisRadarGated` — 2 axes bars horizontales pour les free spawters, radar 5 axes complet pour Gold. Anti-mensonge PRD §3.1 FR-008.

### 2.2. C1 anti-fraude exclusion seed détectée et fixée

Le finding C1 (Edge Case Hunter) — `unique_spots` ne filtrait pas `is_seed=true` — était un **bypass anti-fraude critique** (un user en mode démo pouvait franchir des stades artificiellement avec les seeds). Fix 1-liner mais impact business énorme. Test ajouté pour verrouiller l'invariant.

### 2.3. Pattern in-flight Set guard pour célébrations concurrentes (M7)

Bug subtil : 2 `registerSpawt` async concurrents pouvaient tous deux compute `updated.stade = 'explorateur'` et lever 2 célébrations. Fix : `Set<Stade>` module-level synchrone qui agit comme verrou avant le set pending. Pattern réutilisable pour toute action async qui mute state partagé.

### 2.4. Tests de régression pour chaque CRITIQUE/MAJEUR

15 nouveaux tests ajoutés couvrant C1 (is_seed exclusion), M2 (reset purge cross-user), M3 (anti-replay order), M7 (in-flight guard), M8 (multi-stade unlock), D4 (current_title sync writer). Garantit que les régressions sont détectées au CI.

## 3. Ce qui a coincé

### 3.1. Bug régression migration 0023 service_role bypass manquant

Pendant l'application des triggers BEFORE UPDATE (migration 0023 admin Chunk B), j'ai oublié que `auth.uid()` retourne NULL quand le caller est `service_role` (Edge Functions). Conséquence : les triggers rejetaient toutes les actions Edge Function moderate-spawter !

Fix : check `current_setting('request.jwt.claims', true)::json->>'role' = 'service_role'` en tête de chaque trigger, RETURN NEW direct si trusted. Détecté avant déploiement final (migration mise à jour live via MCP + fichier repo aligné), donc pas de fuite prod.

**Lesson** : tout nouveau trigger qui check `auth.uid()` doit explicitement gérer le cas service_role (sinon il casse les Edge Functions silencieusement).

### 3.2. Tests in-flight Set persistance entre tests

Le `__celebrationInFlight` Set étant module-level (singleton Node import cache), il persistait entre les tests Jest. Premier test consumait, deuxième test trouvait le set déjà rempli → célébration skip → assertion fail.

Fix : `useSpawterStore.getState().reset()` au début du `beforeEach` (reset() clear aussi le set in-flight). Pattern à généraliser pour toute mutation module-level.

### 3.3. Story 5.3 spec "rang" ambigu

Le finding D6 a soulevé que la spec UX-DR12 mentionne "rang" au recto de SpawterCard, mais l'implémentation ne rend que le "stade". Décision retenue D6=B : "rang" = "stade" (déjà rendu en haut-droite) — pas de tech debt server-side requise pour calculer un vrai rang chronologique d'inscription. À reprendre Sprint 2 si Madame Sun veut un vrai numéro de rang.
