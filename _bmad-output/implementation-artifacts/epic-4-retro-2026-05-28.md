## 3. Ce qui a coincé (lessons)

### 3.1. Story 4.10 spawter onglet — bug C1 propagation coords

Le sweep adversarial post-PASS-2 a trouvé que `buildManualSpawt(userLat, userLng)` recevait les coords du **lieu** au lieu des coords du **user** (inversion ordre arg). Le test E2E aurait dû taper "Spawter ici" et vérifier les coords du SpawtCheckin écrit en DB. Non-couvert par les tests unit.

**Lesson** : un test d'intégration mock léger sur les actions store + data-source ferait foi sur ce type d'inversion d'arguments. À considérer Sprint 2.

### 3.2. Story 4.9 PlaceReviews — RLS bloquait silencieusement la lecture

Découvert pendant la session post-PASS-2 (pas dans le sweep adversarial initial) : la RLS `spawt_checkin_select_own` (= owner only) bloquait le PlaceReviews fetch côté mobile, même pour les seeds. Plus la `spawters!inner` join qui filtrait out tous les avis d'autres spawters (RLS spawters_select_own).

Fix livré : migration 0021 (3 changements RLS) + 0022 (helpers progression) appliqués via MCP + capturés en fichiers repo.

**Lesson** : tester le smoke test `listReviewsForPlace` avec un user RÉEL non-owner avant de fermer la story. La RLS est souvent le piège silencieux.

### 3.3. Sprint 4 PASS 2 retro classée `pending` au lieu de `optional`

Status invalide YAML noté dans `/bmad-sprint-status`. Correction live dans ce commit (passe à `done`). À l'avenir : utiliser seulement les statuts canonical (`optional` / `done`).

### 3.4. Migration backfill manquant Epic 5 (M4 found in CR Chunk A)

Migration 0014 (Story 5.1 spawter_progression) n'a pas inclus le backfill `INSERT INTO spawter_progression SELECT id, 0, 'touriste' FROM spawters WHERE NOT EXISTS`. Conséquence : 11 spawters seed pré-existants n'avaient pas de row → premier UPDATE client échouait silencieusement. Fix livré dans migration 0022.

**Lesson** : toute migration qui crée une nouvelle table 1:1 avec une existante doit inclure un backfill ou un comment expliquant pourquoi pas (par exemple si la nouvelle table est append-only on-demand).
