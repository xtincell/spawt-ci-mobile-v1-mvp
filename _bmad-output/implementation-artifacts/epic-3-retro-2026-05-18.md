## 2. Ce qui a marché

### 2.1. Passe dev-story unique de 9 stories — cohérence cross-cutting

Epic 2 = 4 commits étalés, 1 story de complétion (2.3a) extraite mi-review. Epic 3 = **1 seul commit** livrant 9 stories. Le pattern « passe unique » a produit des bénéfices structurels qu'un découpage story-par-story aurait raté :

- **Coordination atomique des coupling** : `MatchingContext.saved_place_ids` (Story 3.6) + `FAVORITE_BONUS` (Story 3.3b) + caller refactor `(tabs)/index.tsx` + `place/[id].tsx` livrés ensemble. **Aucune fenêtre où un caller serait cassé**. Story-par-story aurait introduit une transition `in-progress` où l'AC #5 Story 3.6 (refactor callers) est livrée avant 3.3b — donc breaking.
- **Coupling header fiche lieu** : Stories 3.4 (header overlay back/cluster) + 3.6 (heart toggle) + 3.7 (share button) coordonnées en un seul PR. Pas de Story 3.7 qui reçoit une fiche déjà refondue puis ajoute son bouton — tout est livré simultanément.
- **Cross-cutting Story 3.5 → 3.3c** : icône search dans `Masthead` ajoutée pendant la même passe que la création de `(tabs)/index.tsx` HomeD canonique. Aucun « TODO wire search icon ».
- **Test coverage cohérent** : 153 tests passants tous en même temps, pas de 3 phases successives qui chacune cassent un test temporaire.

**À garder** : pour les epics où les stories sont fortement couplées par des extensions de signatures partagées (`MatchingContext`, header layout), **autoriser la passe dev unique multi-story** au lieu de forcer le séquencement. La règle « 1 story → review → next story » crée du churn quand le couplage est dense.

**Trade-off à conscientiser** (voir §3.1) : la passe unique **interdit le feedback loop par round review** entre stories — toute la dette de review s'accumule en une seule fournée.

### 2.2. Moteurs purs cible #1 — pattern fortifié

3 moteurs purs livrés en Epic 3 : `weighted-rating.ts` (15 tests propriétés mathématiques), `matching.ts` enrichi (23 tests, gel `WEIGHTS` PRD §8.1), `search.ts` (NFD accent-insensitive). Tous :
- **Totaux** : aucun `throw`, retour null/0/[] documenté pour edge cases
- **Sans I/O** : pas d'AsyncStorage, pas de Supabase, pas de timer
- **Compatibles Deno** : pure JS (`Math.*`, `Number.*`, `Date`), portables Edge Functions Story 4.7+
- **Gel d'invariants par tests** : `STADE_WEIGHTS = [1, 1.5, 2, 2.5, 3]` snapshot, `WEIGHTS = [0.15, 0.30, 0.30, 0.10, 0.15]` snapshot. Toute modif = test casse, force la revue.

**Pattern figé** : tout nouveau moteur métier passe par 4 critères avant merge — total / sans I/O / Deno-compatible / tests d'invariants. Cohérent project-context §Testing Rules « cible #1 ».

### 2.3. Zod parse fail-safe à la frontière Supabase

Story 3.3a a livré le pattern `parseRows` dans `data-source.supabase.ts` :
- Pivot DB flat (`lat`, `lng`, `descriptive_address`) → TS nested (`location: {...}`) documenté en commentaire
- `PlaceWithAdnSchema.safeParse(candidate)` — **pas** `parse()` qui throw
- Row corrompue → drop + `__DEV__ console.warn`, le reste de la liste continue
- 1 row corrompue ne casse pas tout le feed (dégradé 11/12 vs crash total)

**À garder** : pour toute nouvelle lecture Supabase qui retourne un type métier, passer par un schéma Zod en bordure avec `safeParse` + drop-row + dev-warn. Cohérent architecture §Data Architecture « échec de parse → fallback propre ».

### 2.4. UUID séquentiels lisibles pour les seeds — side-effect bonus

Décision Story 3.3a : `place_bo_zinc` (slug) → `00000000-0000-0000-0000-000000000001` (UUID séquentiel 1-12). Bénéfices observés :
- **Traçabilité debug** : un dev qui lit `...000000007` devine « 7e seed » sans grep
- **Side-effect bonus inattendu** : `analytics.ts` ligne 243 `UUID_RE` regex matche désormais → `place_id` n'est plus stripé à `null` dans les events `feed_card_clicked` / `place_viewed`. Bug latent depuis Story 1.7 résolu silencieusement.
- **Compatible Supabase** : PostgreSQL `uuid` accepte tout UUID syntaxique 8-4-4-4-12, pas besoin du v4-strict

**À garder** : UUIDs séquentiels pour les seeds dev (lisibilité audit). `gen_random_uuid()` côté DB pour les vraies entrées (Story 6.2 Admin CRUD).

### 3.4. `applyModeFilter` heuristique non testée

Story 3.3c a livré `applyModeFilter(places, mode)` avec un mapping ad-hoc :

```ts
case "traine": return places.filter(p => p.price.tier <= 2 && p.adn.axe_decontracte_habille < 0);
case "decouvre": return places.filter(p => p.adn.axe_populaire_prive > 0 || p.signals.includes("decouverte"));
case "tribu": return places.filter(p => p.adn.axe_decontracte_habille < 0.2);
case "chic": return places.filter(p => p.price.tier === 3 || p.adn.axe_decontracte_habille > 0.3);
case "vite": return places.filter(p => p.adn.axe_informel_etabli < 0);
```

**Aucun test unitaire** sur cette fonction. Risque :
- Mode `tribu` peut ramener 0 lieux si les seeds n'ont pas la bonne distribution → EmptyState « le chat tousse » s'affiche systématiquement
- Mode `vite` peut ne jamais matcher des lieux pertinents
- Si l'alpha montre que les modes ne fonctionnent pas, le bug est silencieux (fallback EmptyState gracieux)

**Lesson** : tout helper avec logique métier (même 5 lignes) qui filtre la donnée présentée à l'utilisateur **doit avoir un test unit** avec un dataset fixture. Pattern à enforcer dans le skill `bmad-dev-story` (auto-suggérer un test fixture quand un filter est créé).

**Action** : ajouter `app/src/lib/__tests__/feed-mode-filter.test.ts` Round 1 patches.

## 4. Découvertes techniques durables Epic 3

1. **`STADE_WEIGHTS = [1, 1.5, 2, 2.5, 3]` figé via `satisfies Record<Stade, number>`** + test snapshot inline pour gel d'invariant. Pattern reproductible pour toute constante PRD-référencée.
2. **`Math.round(v * 10) / 10` pour arrondir à 1 décimale dans les moteurs purs** — pattern stable, testé dans `weighted-rating.ts` et exporté implicitement.
3. **`incrementalWeightedRating(current, newReview)` accumulator pattern** — preserves `sum_weighted_notes` + `sum_weights` pour éviter recompute O(N). Préparé V1, branché Story 4.7 (Edge Function update ADN).
4. **`MatchingContext` étendu avec breaking — refactor callers même PR** — pattern à reproduire pour toute extension d'API interne : breaking + refactor + tests, **jamais** breaking sans refactor.
5. **`rankPlaces` helper avec tiebreaker `id.localeCompare`** — déterminisme reproductible cross-device. À étendre quand un classement serveur précalculé arrive (Sprint 2+).
6. **`haversineKm` exporté depuis `matching.ts`** au lieu d'extraire un `lib/geo.ts` premature. Règle « extraire en module quand 3-4 helpers cohabitent ».
7. **Migration SQL 0010 avec `.down.sql` appairé** + RLS SELECT public sur `is_published = true` + index partiels filtrés `WHERE is_published = true` (perf + RLS-aware).
8. **Zod regex permissive vs `.uuid()` strict** — décision pragmatique quand un format compatible PostgreSQL `uuid` ne match pas la spec RFC 4122 v4. Pattern à appliquer aux seeds dev futurs.
9. **`parseRows` helper avec `safeParse` fail-safe + pivot DB flat → TS nested** — pattern réutilisable pour toute lecture Supabase avec schéma Zod côté frontière.
10. **UUID séquentiels `00000000-...-NNNNNNNNNNNN` pour seeds dev** — lisibilité + traçabilité + side-effect bonus `UUID_RE` analytics.
11. **`useFocusEffect` + `useRef<boolean>` dedup pour analytics 1×/session** — `feed_viewed` ne re-déclenche pas au retour de tab. Pattern reproductible pour tous les events « first view per session ».
12. **`viewabilityConfig { itemVisiblePercentThreshold: 50, minimumViewTime: 500 }` + `useRef<Set<string>>`** — dedup `feed_card_impressed` par place_id. Empêche les impressions fantômes lors d'un scroll rapide.
13. **`FlatList horizontal pagingEnabled snapToInterval`** — carrousel natif RN sans lib tierce, 0 KB bundle add.
14. **Modal RN natif pour bottom sheets V1** — `Modal animationType="slide"` suffit pour search/filter sheets, pas besoin de `react-native-bottom-sheet`.
15. **API native `Share.share`** suffit pour V1 partage WhatsApp — `react-native-share` (15+ KB) déferé jusqu'à V2 attachment image.
16. **`Linking.openURL("tel:" / "whatsapp://send?")`** pour CTAs natifs — fallback gracieux si app absente.
17. **Accent-insensitive search via `.normalize("NFD").replace(/[̀-ͯ]/g, "").toLowerCase()`** — pattern stable, ~3 LOC, gain UX énorme (clavier rapide CIV).
18. **`getRecentSearches`/`addRecentSearch` cap 10 FIFO + dedup** dans `storage.ts` — pattern reproductible pour autres listes récentes (lieux visités, etc.).
19. **`savedPlaceIds: Set<string>` Zustand** + clone immutable à chaque toggle = état cohérent même sur rapid-clicker. Pattern à appliquer aux toggles futurs (Coup de Cœur, Tanière V2).
20. **`AdnTags` chips polarité variant `gold`/`dark`** — pattern UX où la polarité d'un axe ADN détermine la couleur, threshold `|valeur| ≥ 0.5` pour show/hide.
