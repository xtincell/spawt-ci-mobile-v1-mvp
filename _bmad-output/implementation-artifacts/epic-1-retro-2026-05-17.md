## 2. Ce qui a marché

### 2.1. Pattern brownfield-first

**Story 1.1** : l'agent a découvert via `git log` + grep que `tokens.ts` était déjà aligné dans le commit `979ee2d` (bootstrap Moka). La story s'est réduite à un seul patch (`state.danger`) au lieu d'une réécriture. Sans cette vérification préalable, on aurait ré-écrit ~200 lignes pour rien.

**À garder** : checklist « git log + grep semantic » avant tout plan de story brownfield.

### 2.2. `deferred-work.md` comme mémoire structurée

23 items deferrés avec rationale + story d'origine + cible follow-up. Zéro perte de signal entre reviews. Aucun item n'est tombé dans l'oubli ; chacun a un point d'attache futur clair.

### 2.3. Triple gate discipliné

`tsc --noEmit + lint:vocab + i18n:check` a tenu 100 % du sprint. Aucune fuite de hex en dur, aucune string FR hardcodée hors `fr.json`, aucun vocab interdit. La discipline pre-commit a tenu malgré 5 commits + 30 patches.

### 2.4. `satisfies Record<…>` plutôt que `as`

Idiome canonique appliqué dans `typography.preset`, `EVENT_TO_SIGNAL`, `ZUSTAND_CJS` map. Garantit l'exhaustivité au compile-time sans flatten du type littéral. Toute future entrée manquante → erreur TS au build, pas un `undefined` silencieux à l'insert.

### 2.5. D1-D4 résolus en review = 4 stories de rework évitées

En particulier **D2** (queue pre-auth pour events funnel) qui aurait perdu les 5 events critiques §16.1 si on l'avait laissé silencieux. Pattern industry-standard Stripe/Segment retenu, déjà wiré dans `_layout.tsx` (commit `3b83b49`).

### 2.6. 12 primitives → 16 patches absorbés sans casser les callers

Story 1.3 a généré 16 patches review mais les 4 composants existants (Story 1.4) ont été re-dérivés *sans toucher leurs APIs publiques*. Aucun caller cassé en 8 fichiers. Coexistence temporaire `PalaisRadar` neuf à côté d'`AxisRadar` ancien jusqu'à Story 1.4.

## 3. Ce qui a accroché

### 3.1. Spec ↔ implémentation drift

La table « État Sprint 1 » de `supabase/README.md` est restée `⏳` pour les Stories 1.6/1.7/1.8 alors qu'elles étaient `done` dans `sprint-status.yaml`. Caught uniquement par l'Acceptance Auditor en cross-check.

**Pattern récurrent** : marquer une story `done` ne propage pas automatiquement aux docs satellites. Pas un bug fonctionnel, mais ça use la confiance dans les checkboxes.

### 3.2. Piège PostScript iOS (Story 1.2)

`Klinsman-Bold.otf` embarque en réalité `KlinsmanTypefaceBold` dans sa table OpenType `name` (nameID=6). Découvert uniquement parce que la review a posé la question.

iOS résout `fontFamily` par PostScript name embedded, **pas** par filename. Solution : script Python qui lit la table `name` OpenType de chaque police avant le wiring.

**Lesson** : pour iOS, lire programmatiquement le PostScript name embedded avant de wirer `expo-font`.

### 3.3. `analytics.test-types.ts` bundlé par Metro (Story 1.7)

Test compile-time uniquement (`@ts-expect-error`) mais l'extension `.ts` + emplacement `src/lib/` faisait que tout son corps `track(...)` finissait dans le bundle JS prod. Métriques : ~60 LOC inutiles dans le bundle, plus quelques appels factices à `track()` au boot.

Patché en `__tests__/types/analytics.test-d.ts` (Metro exclut `__tests__/` par défaut, et `.test-d.ts` est la convention `tsd`).

**Lesson** : type-only test files = `.test-d.ts` sous `__tests__/types/`.

### 3.4. 4 décisions architecture tranchées en review, pas en planning

Stories 1.5-1.8 ont généré **D1-D4** que le BMad-dev a refusé de trancher seul (cascade-delete vs append-only, pre-auth queue pattern, batching, role privileges). Comportement correct (l'agent a respecté « ne tranche pas, signale »), mais ça veut dire que 4 invariants d'architecture ont été tranchés en *review*, pas en *planning*.

**Lesson** : ces invariants doivent émerger à la phase `bmad-check-implementation-readiness` ou `bmad-create-story` (Phase 3), pas en code review (Phase 4).

## 4. Découvertes techniques durables

1. **PGlite (`@electric-sql/pglite`) pour validation sémantique SQL sans Docker** — Postgres en WASM Node, applique migrations + teste triggers d'invariants. Confirmé sur les 5 migrations Epic 1, tests d'invariants en runtime (stade anti-régression, consent set-once, append-only, customer back-edge, flag_code format).
2. **`satisfies Record<EventName, SignalType>` over `as`** — idiome figé pour mappings exhaustifs.
3. **`DEFAULT auth.uid()` sur colonnes `spawter_id`** — wrapper client n'a pas à passer explicitement spawter_id, RLS valide quand même en `WITH CHECK`.
4. **Queue pre-auth `spawt:analytics:pending`** — buffer in-memory + AsyncStorage cap 200 FIFO, flush sur `auth.onAuthStateChange('SIGNED_IN')`. Industry-standard Stripe/Segment/PostHog.
5. **Constraint trigger DEFERRABLE INITIALLY DEFERRED** pour back-edges spawters↔customers — laisse les transactions multi-table cohérentes.
