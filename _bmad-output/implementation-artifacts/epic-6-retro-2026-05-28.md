## 2. Ce qui a marché

### 2.1. Bootstrap spawt-admin séparé du mobile

Décision Story 6.1 : codebase admin entièrement séparée (`spawt-admin/`) plutôt que monorepo avec `app/`. Avantages confirmés :
- Pas de pollution bundle mobile (Vite + Recharts ne touchent jamais le bundle Expo)
- Stack admin moderne (React 18 stable, vs React 19 mobile RC) → moins de surprises
- Deploy séparé Cloudflare Pages → cycle indépendant
- Tests vitest isolés (vs jest mobile)

### 2.2. Sweep adversarial Chunk B a remonté 6 CRITIQUE sécurité

Le sweep a détecté :
- **C1** : soft-delete review cassé silencieusement (CHECK constraint reject)
- **C2** : escalade privilège staff via UPDATE columns non-whitelist
- **C3** : altération preuves staff via UPDATE non-restrictif
- **C4** : audit log mensonger (no error checks Edge Function)
- **C5** : format error `account_banned` non-conforme spec
- **C6** : routes admin accessibles sans session

**6 trous critiques** qui auraient survécu en prod sans le sweep. Justifie le coût du sweep + ROI clair pour Sprint 2 standardiser la pratique.

### 2.3. Migration 0023 — column-level guards via BEFORE UPDATE triggers

Pattern propre pour faire du column-level access control (PG ne supporte pas natively le column-level RLS). Helper `assert_spawters_update_columns_allowlist()` + `assert_spawt_checkin_staff_update_columns()` SECURITY INVOKER avec :
- Bypass service_role (sinon Edge Functions cassent)
- Owner = tout autorisé (cohérent RLS own-only existante)
- Staff = whitelist explicite (is_banned, warning_count, deleted_at, etc.)
- RAISE EXCEPTION sinon

Réutilisable pour toute table sensible Sprint 2.

### 2.4. Atomicité Edge Functions via rollback explicite

Pour `moderate-spawter` ban : sequence `UPDATE spawters → JWT invalidate → soft-delete reviews → audit`. Chaque step a un error check, et l'échec JWT invalidate rollback le ban (UPDATE spawters set is_banned=false). Pour `seed-inventory` : audit log batch avec errors granulaires par place + check existence seed_spawter avant tout insert.

Pattern à réutiliser : "rollback explicite" + "audit log avec error check + best-effort fallback" sont devenus les défauts Edge Functions.

### 2.5. CORS preflight handlers explicites

Avant CR : Edge Functions sans OPTIONS handler → browser bloque les calls depuis spawt-admin (Cloudflare Pages → supabase.co cross-origin). Maintenant : 3 Edge Functions ont leur preflight OPTIONS + headers Access-Control-Allow-* explicites.

## 3. Ce qui a coincé

### 3.1. Volume des findings Chunk B (3x plus grand que Chunk A)

3061 lignes Chunk B vs 1860 lignes Chunk A → ~105 findings vs 64. Le triage a pris ~30 min pour dédup et classifier. Le ratio bug/LOC est similaire, mais l'absolu grand → fatigue cognitive lors du patch sequence.

**Lesson** : pour les futurs sweeps > 3000 lignes, considérer 2 sub-chunks (par exemple admin web + Edge Functions séparés). Aurait permis du focus.

### 3.2. SDK Supabase `auth.admin.signOut(user_id)` signature ambigüe

Le sweep a soulevé que `supabase.auth.admin.signOut(spawter_id, "global")` (SDK v2.45) ne fait peut-être pas ce qu'on croit (signature `signOut(jwt, scope)` selon les docs). Trade-off : `auth.admin.updateUserById(uid, {user_metadata: {banned_at}})` force le refresh des claims au prochain JWT refresh (< 1h TTL). Pas du "force logout immédiat" mais c'est le meilleur GoTrue V1.

**Lesson** : verify systématiquement les signatures SDK admin avant prod. Sprint 2 = considérer un blacklist JWT serveur si on a besoin de logout immédiat.

### 3.3. Refine v5 resource `place_adn` non-déclarée

PlaceForm.tsx utilisait `useCreate({ resource: "place_adn" })` et `useUpdate({ resource: "place_adn" })` sans que la resource soit déclarée dans `<Refine resources>`. Marchait par chance (dataProvider générique fallback). Détecté + fixé Chunk B (m12).

**Lesson** : tout `useCreate/useUpdate` doit avoir sa resource déclarée. Considérer un ESLint custom rule Sprint 2.

### 3.4. uploadPlacePhoto retour type changed cascade impact

Changer le retour de `Promise<string | null>` à `Promise<UploadResult>` avec error structurée a forcé à patcher PlaceForm. Le typecheck a directement détecté le break, ce qui est bon. Mais souligne que les fonctions exposées doivent avoir une API stable (ou être marquées `@internal`).
